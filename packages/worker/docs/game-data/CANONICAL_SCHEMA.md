# Canonical filesystem schema v1

`dist/<game-version>/manifest.json` records game/resource version, source repository and commit, extraction timestamp, schema inventory hash and counts. Set `SOURCE_DATE_EPOCH` for a reproducible timestamp. `coverage.json` inventories every checked-out JSON table. `diagnostics.json` records source-path-specific gaps. `raw-evidence/` copies every inventoried JSON file byte-for-byte and records its SHA-256, so unsupported or currently out-of-scope records remain available inside the versioned dataset.

Entities are JSONL files in `entities/<kind>.jsonl`. Every record has `id`, `kind`, `version`, source repository and commit, `source` (file, row and raw path when applicable), and `raw` for the exact source record. Typed fields add raw IDs and resolved references. Kinds currently emitted include quest, quest_type, quest_chapter, quest_tree_chapter, quest_tree_node, quest_node, plot_step, scene, flow, flow_state, action, nested_action, talk_item, narration, player_choice, branch, phone_message, speaker, character, npc, chat_partner, short_message, random_plot, plot_guest, item, area, map_block, source_reference, cutscene, cutscene_variant, video_qte, caption, subtitle, audio_event, voice_reference and asset_reference. Additional review/fragment/music records are retained under their own kinds.

The global graph is `graphs/global.jsonl`; `graphs/global.json` describes the JSONL node/edge files. Each edge contains `from`, `to`, `type`, `basis`, `source`, `raw_path`, `version`, and `relation` (`explicit_reference`, `authored_order`, or `source_array_adjacency`). Missing references are diagnostics, never invented target nodes. `graphs/quests/<QuestId>.json` contains the reachable node-ID set and source-backed edges for that quest; quest prerequisite/reference edges are excluded from that traversal. `indexes/quest_graphs.jsonl` provides sizes and paths.

`localization/<locale>.jsonl` contains string MultiText and numeric speaker/subtitle namespaces. A row retains key, locale, content, raw masked content when applicable, redirect index and source positions. Each value has a resolution state: `resolved_nonempty`, `resolved_empty`, `missing_key`, or `broken_redirect`. `localization/coverage.json` counts these states per locale against the union of source identities across locales; an empty string remains an explicit value and is not counted as translated text. `localization/all-locales.jsonl` groups exact `(namespace, key)` identities with `values_by_locale`. English text in entities is a convenience field, not identity.

`coverage-summary.json` records Tier 1/2/3 inventory counts, TalkItem accounting, PlotAudio reference coverage, cutscene resolution, supplemental narrative-reference records, strict-coverage findings and localization metrics. Tier classification is separate from parser status: `normalized`, `partially_normalized`, `raw_evidence_only`, and `out_of_scope` describe how the compiler treats each table. A `source_reference` entity retains a full raw row when only explicit reference fields have been normalized; it does not imply that the rest of that table's runtime semantics are understood.

Ancillary exact-reference normalizers currently cover interaction, bubble, LevelPlay, minigame and battle flow pointers, QuestId reference configs (including exact instance-dungeon RelatedQuestId), map-block metadata and video QTEs. Full edge raw paths include row positions and `<json>` markers when the original field held serialized JSON. Battle dialogue uses `PlotName + FlowId + StateId` only where the resulting exact flow and state identities exist.

Stable local IDs use raw source identity plus array positions where IDs are only local or absent. Examples: `quest:119000000`, `quest_node:119000000:2`, `flow_state:<StateKey>`, `action:<StateKey>:<action-index>`, `talk_item:<StateKey>:<action-index>:<talk-index>`. Source array positions remain explicit fields. All unknown/unsupported types retain their raw row and generate diagnostics.

This is a versioned interchange representation for later DB/KG import. It does not claim to encode actual player traversal or infer character identity from equal names/numbers.

## Quest progression vocabulary

`coverage-summary.json.quest_progression` counts raw quests, exact type/chapter joins, quest-tree nodes and each explicit tree relation, plus unresolved tree references.

`quest:<QuestId> → quest_type:<Type>` (`has_quest_type`) and `quest:<QuestId> → quest_chapter:<ChapterId>` (`in_quest_chapter`) come from exact QuestData foreign keys. The separate `quest_tree_node:<Id> → quest_tree_chapter:<ChapterId>` uses QuestTree's own chapter table. `quest_tree_node → quest` (`quest_tree_contains_quest`) records each `QuestArray[i]` with its array position as evidence, without asserting play order within that array. `quest_tree_predecessor`, `quest_tree_next`, `quest_tree_main_node`, and `quest_tree_includes_node` each retain their distinct raw field and source position. `requires_quest` still means an explicit `PreQuest` runtime condition; it must not be substituted for a quest-tree edge. All of these are source relations, not semantic event or causal edges.

After DB import, `graph.edge_evidence.release_id` scopes each source edge's evidence to the snapshot that actually contained it. `GET /quests/{id}/continuity` reports imported version observations, source-backed classification and tree neighbors. `GET /graph/path?from=...&to=...&mode=quest_sequence&game_version=...` returns a bounded path through source relations with edge direction and evidence; a graph path does not prove chronology or a played route. `first_observed_game_version` means the earliest **imported** snapshot with a quest, not the game's debut patch.
